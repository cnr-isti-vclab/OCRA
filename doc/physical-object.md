The metadata model for the physical object is defined in the `physicalObjectMetadata` field of the project document in MongoDB. This is a free-form JSON object that can contain any metadata fields relevant to the physical object, such as title, description, creator, date, etc. 

The important part is that the source of the metadata is captured in the `sourceUri` field, which is a required field that indicates where the metadata was obtained from. This could be a URI pointing to an external resource such as ECHOES, Wikidata, ARCO, or any other source. The `sourceType` field indicates the type of source, which can be used to determine how to interpret the metadata and how to extract relevant fields for caching in the `dublinCore` field. The `dublinCore` field is an optional field that can contain cached metadata fields extracted from the source, such as title, description, creator, date, etc. This allows for easier querying and indexing of the physical object metadata without having to dereference the source URI every time.

Different sources for the metadata may have different structures and fields, so the `physicalObjectMetadata` field is designed to be flexible and accommodate any structure. The only requirement is that the `sourceUri` and `sourceType` fields are present to indicate where the metadata came from. The rest of the metadata can be structured in any way that makes sense for the specific source and use case.

The Ocra application allow to the user to get the metadata for the physical object from different sources, and to update the `physicalObjectMetadata` field with new metadata obtained from these sources. For each different source, the application can implement specific logic to extract relevant metadata fields and cache them in the `dublinCore` field for easier querying. This way, users can have a rich metadata representation of the physical object that is sourced from multiple places and can be easily accessed and indexed within the application. This part of the code is modular and designed to be extensible, allowing for new sources and metadata structures to be added as needed without affecting the overall data model. 

Initially the application will support a few specific sources such as ECHOES, Wikidata, and ARCO, but the design allows for any source to be added in the future as long as it provides a URI and a type. The metadata extraction process can be triggered at HDT creation time or later, allowing for flexibility in how and when metadata is obtained and cached.
